## 全局执行规则

1. 金额始终以“分”的整数存储；任何 UI 输入先通过 `Core.yuanToCents`。
2. 运行时不得加载 CDN、字体、埋点、统计 SDK、云端 AI 或远程配置；构建期依赖仅允许出现在第五阶段的小程序工程。
3. 测试只使用仓库内虚构数据。真实账单不得写入仓库、终端日志、截图或外部服务。
4. 手动记账和账单导入始终是并列一级入口；任何增强都不能让导入失败阻塞手动记账。
5. 变更数据结构必须提供向前迁移、旧备份恢复测试和失败回滚路径；禁止静默丢字段。
6. 修改 Web 前端静态资源时，同步递增 `js/app.js` 版本与 `sw.js` 缓存键；正式发布前两者必须完全一致。
7. 每个工作包先写外部行为测试，再实现；不得通过降低断言、删除 fixture 或跳过测试制造“通过”。
8. 每个阶段使用独立分支和小步提交；不要改写已有提交，不要覆盖用户的无关修改。
9. 对外发布、上传微信审核、创建远端仓库或推送代码都需要用户单独授权；本执行包只授权本地实现与验证。

## Agent 交接协议

每个实施 Agent 开工时应：

1. 依次读取 `STATUS.md`、`TEST.md`、本索引和目标阶段 `IMPLEMENTATION.md`。
2. 执行 `git status --short`，确认并保护已有未提交修改。
3. 执行目标阶段的基线检查；基线失败时先记录，不把历史失败算作本次回归。
4. 一次只领取一个工作包，按文档中的依赖顺序推进。
5. 完成后给出：修改文件、测试证据、未解决风险、提交哈希、下一工作包建议。

## 文档维护责任

- 产品与阶段状态：更新 `STATUS.md`。
- 可复现测试证据与缺陷结论：更新 `TEST.md`。
- 面向用户的版本变化：更新 `CHANGELOG.md`。
- 阶段方案发生架构级变化：先更新对应 `IMPLEMENTATION.md` 的“决策记录”，再改代码。
- 实施过程中的用户指令：追加到 `Ledger_Prompt_Log.md`，不得写入真实财务数据。
